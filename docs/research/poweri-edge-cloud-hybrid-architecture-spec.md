## 1. 问题与结论

近期目标是在现有后台中提供面向团队几十人的 Web Agent 能力；长期支持 Desktop、Web、Mobile 访问，并保留本地完整 Agent 的能力。核心问题不是 Web 能否执行工具，而是会话由谁推进、文件以哪里为准、执行权限如何隔离，以及故障后如何判断任务结果。

**决策结论：B 保留战略重点地位，A 承接近期团队 Web 价值，C 保留本地模式；复用完整 Agent 宿主，而不是按 Pi 包名硬拆分跨机器服务。**

战略优先级与交付顺序分开：先用小型 B 闭环验证远程执行路径与 B/C 共用契约；A 的团队交付须经过独立的身份、隔离、生命周期、计量和容量门禁。不能将“工具位置可切换”推导为“活跃会话和文件可无缝迁移”。

## 3. 当前实现、职责词汇与 Pi 三件套

### 3.1 当前事实

当前 Power Web 在 Next.js Node 进程内通过 `createAgentSessionFromServices` 运行完整会话，以 HTTP 命令与 SSE 事件连接浏览器；不能描述成已有 stdio–WebSocket Gateway。NPM 包是全栈应用服务，不是可直接 import 的纯前端组件库。团队后台集成优先复用现有应用入口及协议，具体反代、嵌入方式与身份传递须在 A 阶段验证。

当前实现尚无完整租户控制面。现有 provider 凭据管理不等于租户身份认证；进程内会话 registry、本地会话文件和用户指定 `cwd` 也不构成租户隔离。

### 3.2 逻辑职责，而非强制微服务划分

| 术语 | 职责与边界 |
| --- | --- |
| UI | 输入、事件与产物呈现；查看或控制会话不等于拥有其运行权 |
| AgentHost（会话宿主） | 推进 Agent 循环，管理上下文、会话持久化、compaction、配置与扩展 |
| Execution Environment（执行环境） | 执行获准的工具操作并返回结果；本地执行环境默认不等于安全沙箱 |
| Platform Control Plane（平台控制面） | 身份授权、沙箱生命周期、凭据代理、配额和观测；不与 AgentHost 混为一谈 |
| Workspace（工作区） | 文件及相关工程资源的权威位置；与会话记录的存储位置分别定义 |

沿用项目词汇：**Host Runtime Environment** 指 Web 服务及框架自身的运行环境；**Project Command Environment** 指项目命令获得的环境；**Built-in Project Shell** 指平台提供的项目 Shell 入口。不得把项目环境当成可信宿主环境，也不能遗漏独立于模型工具注册的 Shell 入口。

### 3.3 包依赖不等于跨机器边界

| 包 | 可复用能力 | 不能推出的结论 |
| --- | --- | --- |
| `pi-ai` | 模型协议适配与流式通信 | 本地运行它不代表模型在本地推理；也不意味着必须向客户端下发企业共享密钥 |
| `pi-agent-core` | 有状态的 Agent 循环、工具执行与事件；可接入自定义工具实现 | 内存状态不等于无状态，更不等于可随时丢弃或自动迁移 |
| `pi-coding-agent` | 创建 core Agent，并组合完整 AgentSession、会话管理、compaction、资源/扩展及工具能力 | 不是放在云端供本地 core 调用的纯工具服务器 |

桌面 B 优先保留完整 `pi-coding-agent` 宿主，用已有工具扩展点接入远程执行；不为实现 B 而重建已有会话能力。若以后采用纯浏览器或移动端 core 宿主，需单独评估持久化、扩展兼容和会话功能的实现成本。

端侧循环可以经认证的模型代理调用模型，企业共享密钥保留在服务端。移动端轻量 JS 循环与在手机运行完整 Linux 工具环境是两个课题，后台连续性另行验证。C 仅表示 Agent 和工具本地部署；完全离线还需要本地模型等条件，不能因此承诺提示、代码绝不发送给云模型。

## 4. B/A/C 部署矩阵与成立条件

| 模式 | 会话权威宿主 | 工具执行 | 工作区权威 | 生命周期与定位 |
| --- | --- | --- | --- | --- |
| **B：理想方向/战略重点** | 本地完整 AgentHost | 远程受隔离执行环境 | 首阶段 PoC 为远程工作区 | 本地调度、远程执行；本地宿主停止后不能自动推进后续 Agent 轮次 |
| **A：端侧能力降级时的托管兼容形态** | 远程隔离的完整 AgentHost | 远程受隔离环境，可与宿主同处隔离边界 | 远程工作区 | 承接团队 Web；客户端离线仍可运行是必须实现并验证的目标 |
| **C：本地执行特化** | 本地完整 AgentHost | 本地执行环境 | 本地工作区 | 保留当前能力；不因称为本地模式而获得额外安全隔离 |

- **B/C 共用宿主能力**，在执行位置维度可通过适配器变化实现特化；前提是工具和工作区语义一致，不承诺现有会话即时切换。
- **A/B 改变会话宿主位置**，不是换执行器即可完成。会话所有权、在途操作、扩展配置与持久状态交接均在一期之外。
- 共用远程沙箱服务不等于共用租户实例或文件目录。首阶段使用独立测试工作区；后续共享策略须经过授权和隔离验证。
- A 可以复用当前进程内宿主及 HTTP/SSE 能力，不强制改用旧 stdio–WS bridge，也不要求所有模块独立部署为微服务。

## 5. 会话、工作区与执行契约

### 5.1 单会话单权威宿主

一个会话同一时刻只有一个宿主推进循环和提交权威状态。多个客户端连接同一宿主是远程访问，不是多个 Agent 并行推进同一会话。首阶段创建后固定宿主位置；冲突操作须明确拒绝或可观测地串行处理，不能静默产生第二个写入者。

B 的会话状态由本地宿主管理，远程执行端仍需要保留操作身份、运行状态及结果以支持对账；“远程不运行 Agent 循环”不等于“远程零状态”。A 的客户端连接与宿主存活需要解耦，但浏览器重连、宿主崩溃恢复和沙箱重建是三种不同故障，不得统一宣称已支持。

### 5.2 工作区权威与跨边界能力清单

B PoC 采用远程权威工作区，C 采用本地工作区。两者可以使用内容相同但独立的测试样本，不做实时双写或自动同步。远程不可用时不得静默回退为宿主文件操作。

必须逐项确定路由、明确保留为宿主职责或拒绝不支持的能力：模型文件工具、独立 Shell、文件浏览/上传/下载、git/worktree、工作区资源和指令加载、扩展执行、产物预览及路径解析。仅替换四个模型工具不足以覆盖这些入口。宿主配置可保留本地，但必须与远程项目文件明确区分。

### 5.3 优先复用 SDK 接口语义

已有 `ReadOperations`、`WriteOperations`、`EditOperations`、`BashOperations` 及工具定义注入能力，应先复用，不将研究稿中的四个 Promise 方法视为既有 SDK API 或充分协议。

适配器至少保留：二进制/图片读取、编辑换行与 BOM/diff 行为、命令增量输出、取消与进程树停止、超时单位及错误语义、输出截断和相关元数据。操作钩子之外仍可能存在宿主路径检查、资源加载、临时文件与队列行为；必须以完整工具和会话测试验证。不得假设所有 operations 都提供相同的取消参数。

网络边界需要表达操作身份、所属会话/工作区、接受与拒绝、进度、终态、取消及结果查询。这是协议应满足的语义，不提前锁定 WebSocket、具体线格式或供应商 API。

### 5.4 恢复、取消、去重和计量

- 请求接受确认、事件补齐、执行结果对账是不同契约。明确被拒绝与网络故障不能混为一谈。
- 已接受请求的网络重试须关联同一逻辑操作；结果无法确认或去重记录过期时，返回“待对账/unknown”，不能盲目重新执行有副作用操作。
- 事件重放只恢复观察视图，不能据此保证外部副作用 Exactly-Once。需要重试的外部业务工具必须有独立幂等或对账策略。
- 取消请求不等于进程已停止；未确认停止时不能显示“已取消”。已经完成的文件写入不因取消而自动回滚。
- B 宿主停止后，即使远端某个命令仍运行，也不代表完整 Agent 任务继续。首阶段不自动把 B 转为 A。
- 使用量按真实模型调用统计，重连或重放不得重复入账；分别标明输入、输出、缓存读取/写入及费用来源。测试替身产生的数据必须标为测试数据，不能作为真实账单证据。

## 6. 安全与隔离准入

`excludeTools: ['bash']` 仅影响工具注册，不足以关闭独立 bash RPC；`cwd` 也不是文件系统访问边界。因此删除“先禁 bash 即可安全共享上线”的路线。

团队开放前至少证明：

1. 会话、事件、工作区、产物和配置/凭据入口均绑定认证身份并进行服务端授权；猜测资源 ID 或篡改客户端标识不能越权。
2. 用户工具及扩展不在共享可信管理进程中获得任意执行权限；路径穿越、绝对路径和符号链接不能访问未授权资源。
3. 沙箱资源有明确限制，网络按策略限制，包括云元数据、生产内网等敏感目标；需要访问内部业务的工具走受控授权接口。
4. 沙箱内没有不必要的宿主目录、运行时管理接口或企业共享凭据；取消、超时及异常退出可观测，不影响其他工作区的授权边界。
5. 真实执行环境中的负向测试通过。Mock 可以验证错误分支，不能证明 OS 隔离、安全逃逸防护或生产容量。

Docker 可用于受控验证，是否满足后续威胁模型仍需评估；不预设必须自研沙箱控制器或升级到 K8s。仅把 `pi` 放入容器，不会让外部 Next.js 文件/git/API 自动进入容器：须将相应服务纳入隔离边界或逐项路由并验证。

## 8. 测试缝隙与完整会话验收矩阵

**主缝隙是完整会话的外部行为**：从客户端发起任务，经过实际宿主与工具，到事件、状态和产物结果。辅助缝隙是 SDK 执行适配器契约；安全和进程生命周期另需真实沙箱测试。B/C 使用可控模型响应运行同一组场景，验证系统行为而非 LLM 随机输出；真实模型联调单列并明确成本授权。

| 编号 | 外部场景与可观察验收结果 | 首阶段范围 |
| --- | --- | --- |
| V1 | B/C 完成读取样本→修改→执行命令→读取产物的多轮会话；内容与工具语义一致，B 不访问本地项目样本 | 必做 |
| V2 | 命令进度在结束前可见，图片/二进制、编辑换行/diff、长输出截断可正确读取；状态和错误未丢失 | 必做 |
| V3 | 长命令取消、超时后可确认进程终止；不能确认时保留待对账状态；不声称已写入内容回滚 | 必做，进程行为使用真实执行环境 |
| V4 | 在接受确认前后断开工具连接并重连，能区分拒绝、已接受和未知；不因重试重复执行副作用 | 必做，受控故障注入 |
| V5 | 观察端重连后状态与产物一致，补齐视图不重复发命令或累计使用量；不可恢复的历史缺口明确显示 | 必做，不等于保证永久事件归档 |
| V6 | B 宿主停止不被误报为任务已完成或已自动托管；恢复时先核对在途结果，不悄悄创建第二个宿主 | 必做；自动宿主迁移不实现 |
| V7 | 修改工作区身份、越界路径、符号链接和禁止的网络目标被阻断；独立 Shell/文件入口无宿主回退 | 必做，仅用测试数据与获准测试目标 |
| V8 | 沙箱/连接意外终止给出可辨认失败或未知状态，控制侧仍可用；不能把 EOF 当正常完成 | 必做 |
| V9 | C 的会话恢复、分支、compaction 和必要扩展能力不因引入 B 退化；本地/云模型数据去向说明准确 | 必做，复用现有回归并记录缺项 |
| V10 | 实际或标记为测试的模型调用账目可对账，事件重放不重复计数，缓存口径可解释 | 首阶段验证口径；生产持久化另过门禁 |
| V11 | A 客户端关闭后宿主继续工作，重连可访问同一任务；身份授权和各 API 路由均在正确边界内 | 后续 A 交付门禁 |
| V12 | 多租户越权、资源耗尽、并发互斥和使用量故障恢复测试通过，并有可复现容量报告 | 后续团队开放门禁 |

现有 HTTP 命令错误区分、SSE 启动/取消与快照投影、增量事件协议测试可作为先例，但不证明上述远程执行、持久恢复或租户隔离已实现。具体先例见任务书的 Testing Decisions。

## 9. 分阶段范围与退出门禁

| 阶段 | 可开展工作 | 退出条件与禁止事项 |
| --- | --- | --- |
| 首阶段：受控架构验证 | B 小闭环、B/C 会话契约、C 回归及跨边界能力清单 | V1–V10 有测试结果或明确阻塞记录；必做项未通过不得标为完成，更不得自动开放团队访问 |
| A：团队 Web 交付 | 复用完整隔离宿主与平台能力，接入现有后台 | V11 及认证、授权、路由覆盖、生命周期、计量验证通过；不是仅禁 bash 即上线 |
| 团队开放 | 在已声明威胁模型与资源配置下验证多用户运行 | V12 通过；以真实负载测试确认支持规模，不从“团队几十人”推导已支持固定并发 |
| 后续演进 | 按需求评估移动端 A 接入、进一步弹性与恢复能力 | 独立规格与验证，不由首阶段 `ready-for-agent` 自动授权 |

不承诺固定周数、固定并发数或固定空闲回收时间。回收策略需考虑运行中任务、产物留存和恢复；首阶段只清理明确终止的测试资源。生产沙箱供应商、容量配置和保留期限在后续部署规格中确定，不阻塞隔离测试环境中的首阶段验证。

## 10. 两轮 Review 汇总台账

| 议题 | 最终判断 | 处理结果 |
| --- | --- | --- |
| 新定位是否未经授权 | 用户有明确授权 | 撤回第一轮的定位否决；保留历史 ADR 并说明适用范围变化 |
| B/A/C 是否为“普遍最优定理” | 是战略偏好，不是无条件技术定理 | 明确各自宿主、执行位置、工作区及生命周期条件 |
| Pi 三件套能否直接按包拆成端云服务 | 不能；coding-agent 包含 core 与完整宿主能力 | 保留完整宿主，工具接缝优先复用 SDK |
| 四方法执行接口是否充分 | 不足以覆盖工具语义和平台文件入口 | 增加 operations 契约与跨边界能力清单 |
| 禁 bash/设置 cwd 能否安全共享部署 | 不能 | 删除简化上线路线，要求真实隔离与入口授权 |
| 旧 Gateway/bridge/计量是否成熟可直接继承 | 仅部分思路和原型可复用 | 区分完整 Agent 桥与纯工具服务，新增生命周期、去重和持久化门禁 |
| 现有项目是否没有 worktree | 有用户管理能力 | 将缺口限定为自动任务隔离/合并编排，不在一期重建 |
| Request-Replay 是否保证副作用 Exactly-Once | 不能 | 分离请求去重、视图补齐和业务幂等；不确定时对账 |
| C 是否天然离线、绝对私密 | 取决于模型与其他外部服务 | 区分部署位置、模型调用位置和数据去向 |
| RWO 是否永久锁节点或限制单 Pod | 均不能如此概括 | RWO 为单节点读写挂载语义，同节点可多 Pod；不作为永久节点绑定依据 |
| Devin 使用 Firecracker、无 JIT 必过审核、移动性能慢 5–10 倍 | 本轮证据不足以支持这些确定断言 | 不用于选型或验收前提，保留为待一手资料补证的研究问题 |

原对话中反复出现的“100%”“绝对安全”“零风险”没有相应验证；部分研究提问又预设了优劣结论。后续研究应同时记录可行条件、反例、来源与未知项，不能用多份相互引用的总结代替独立证据。

## 11. 范围外、待验证项与资料索引

**一期范围外**：活跃宿主迁移、透明 A/B 切换、自动双向文件同步、自动任务 worktree/合并编排、移动端原生 Shell 与系统推送、K8s 预热池、商业支付结算，以及跨公网多云调度。移动端先采用 A 是建议，不是所有移动端场景的技术必然。
