# PowerI 端云协同首阶段架构验证规格

## Problem Statement

团队希望从现有后台使用具备真实执行能力的 Web Agent，同时保留桌面本地能力并探索本地调度、远程执行。当前系统已经有完整 Agent，但还没有得到验证的多租户控制面和远程执行闭环。

旧规格混淆了 Pi 包依赖与跨机器部署边界，并将“换工具执行器”扩大为“无缝迁移会话、离线持续运行、安全共享部署”。这些承诺会导致重复建设会话宿主、遗漏文件与 Shell 入口，并让尚未验证的原型进入生产。

本任务解决的是**先证明架构能否按既有会话语义成立**，不是一次性实现完整团队平台。

## Solution

保留用户已确认的 B/A/C 关系：B 是长期重点，A 是端侧不承载 Runtime 时的托管兼容与近期团队 Web 交付形态，C 保留本地执行模式。首阶段优先复用完整 AgentSession，在完整会话的外部行为上验证 B 的远程执行与 C 的本地回归。

**本任务可以启动的范围**：受控测试环境中的 B 小闭环、B/C 共用会话契约、跨边界能力清单、真实执行环境的负向测试，以及验证结果记录。B PoC 使用远程权威工作区；每个会话创建后固定唯一宿主；不自动同步文件或迁移活跃会话。

**测试缝隙已由用户确认**：完整会话行为为主，SDK 执行适配器契约为辅；真实隔离、进程停止和故障恢复不能只靠 Mock 验证。

**`ready-for-agent` 的含义**：上述首阶段验证范围可执行，不表示现有能力已通过验证，也不授权团队上线。A 的团队交付仍受主架构文档 V11–V12 等独立门禁约束。

## User Stories

以下故事均属于首阶段的验证与回归需求，不自动创建新的 UI 功能或生产部署要求。

1. 作为一名桌面用户，我希望 B 会话保留完整宿主的会话管理能力，以便远程执行不要求我放弃已有的工作方式。
2. 作为一名开发者，我希望 B 能在明确的远程工作区读取、修改文件并运行命令，以便验证重计算可从本机卸载。
3. 作为一名本地用户，我希望 C 能在独立的本地样本上完成相同任务，以便验证本地执行没有退化。
4. 作为一名用户，我希望任务和产物能够说明其执行位置，以便不会把远程文件与本地文件混淆。
5. 作为一名用户，我希望远程执行不可用时得到明确错误，以便系统不会偷偷改为访问我的本地项目。
6. 作为一名用户，我希望完整多轮任务最终能读取生成的产物，以便验证从工具操作到结果消费的闭环。
7. 作为一名用户，我希望长命令结束前就能观察到进度，以便分辨任务仍在运行还是已经失去连接。
8. 作为一名用户，我希望图片和二进制文件不被错误转换为普通文本，以便远程读取与既有工具语义一致。
9. 作为一名开发者，我希望编辑保留约定的换行、BOM 和差异结果，以便执行位置变化不破坏项目文件。
10. 作为一名用户，我希望大段输出截断时仍能判断内容是否完整并获得约定的后续访问方式，以便不会误用不完整结果。
11. 作为一名用户，我希望取消后能区分请求已收到和进程已停止，以便不会把仍在产生副作用的操作当成已结束。
12. 作为一名用户，我希望已写入的文件不会被系统声称因取消而自动回滚，以便对实际产物有正确预期。
13. 作为一名用户，我希望超时和工具错误保持可辨认的语义，以便知道下一步应等待、修正输入还是核对结果。
14. 作为一名用户，我希望系统区分明确拒绝与连接中断，以便不会把未知结果误当成操作未发生。
15. 作为一名用户，我希望已接受操作的网络重试关联原操作，以便不会无意重复执行有副作用的任务。
16. 作为一名用户，我希望无法确认执行结果时显示待对账状态，以便先核对事实而不是盲目重试。
17. 作为一名用户，我希望观察端重连后状态与产物一致，以便恢复查看时不会重新发起同一任务。
18. 作为一名用户，我希望关闭 B 宿主后不会收到“已自动转云端继续”的虚假提示，以便了解 Agent 循环实际停止的位置。
19. 作为一名会话使用者，我希望冲突操作不能产生第二个权威宿主，以便会话记录与在途工具结果不被并行写坏。
20. 作为一名安全验证者，我希望篡改工作区标识或访问越界路径时被拒绝，以便独立测试工作区的权限边界可被验证。
21. 作为一名安全验证者，我希望独立 Shell、文件接口和资源加载也进入能力清单，以便隔离不会只覆盖模型注册的四个工具。
22. 作为一名安全验证者，我希望真实执行环境阻断禁止的网络目标和宿主资源访问，以便不把 Mock 通过当成隔离成立。
23. 作为一名运维验证者，我希望执行环境异常退出时系统保留可辨认的失败或未知状态，以便不会把连接关闭误报为任务成功。
24. 作为一名计量验证者，我希望使用量来自真实模型调用或明确标记的测试数据，以便事件重放不会制造重复费用。
25. 作为一名计量验证者，我希望输入、输出和缓存口径可解释，以便验证结果能与对应调用记录对账。
26. 作为一名本地用户，我希望会话恢复、分支、compaction 和必要扩展能力被纳入回归，以便新执行路径不损害原有能力。
27. 作为一名项目负责人，我希望每个必做场景有通过证据或明确阻塞原因，以便不会把未验证的设计当成已完成能力。
28. 作为一名项目负责人，我希望验证未通过时停止扩大范围，以便团队不会因一份就绪标签而过早暴露生产数据与执行权限。

## Implementation Decisions

1. **复用完整宿主**：首阶段桌面 B/C 共用现有 AgentSession 能力。core 是有状态循环，coding-agent 是组合完整会话能力的宿主；不把后者另起为 B 的远端纯工具服务器，也不重建其会话功能。
2. **最少的新增接缝**：主要外部契约维持完整会话命令与事件；新增远程执行适配时优先使用现有工具定义注入及 Read/Write/Edit/Bash operations。不得把研究稿中的四方法接口误当既有 SDK API 或完整网络协议。
3. **固定权威位置**：每会话只有一个权威宿主；B PoC 的项目工作区在远程，C 在本地。宿主配置与项目文件分别归属，不做自动双写、透明本地回退或活跃 A/B 切换。
4. **跨边界能力清单**：逐项标记模型工具、独立 Shell、文件浏览与传输、git/worktree、项目资源、扩展及产物访问应路由、保留或拒绝。未支持的远程能力明确拒绝，不能落回宿主文件系统。该清单同时记录后续 A 的路由覆盖风险，但不在本任务实施 A 上线。
5. **语义兼容**：保留二进制/图片、编辑换行与差异、增量输出、取消、超时、截断及元数据语义。operations 之外的宿主路径检查、临时文件和资源加载必须纳入验证，不假定只注入工具就已覆盖。
6. **操作身份与故障语义**：接受确认、进度、终态、取消和结果查询关联同一逻辑操作。明确拒绝与未知结果区分；无法证明副作用未发生时不自动重新执行。事件补齐、请求去重和外部业务幂等分别处理，不承诺通用 Exactly-Once。
7. **生命周期**：观察连接与任务状态分别建模。取消未确认不得报已停止；文件写入不承诺事务回滚。B 宿主停止不自动推进下一轮，也不悄悄转换为托管会话；恢复时先核对在途结果。
8. **受控安全验证**：使用合成数据、独立测试工作区和获准测试目标；验证授权、路径、网络与资源边界。工具排除配置和当前目录不是隔离机制。Docker 可作验证候选，不据此决定生产供应商，也不默认新建调度与回收系统。
9. **计量与模型依赖**：确定性会话测试使用可控模型响应，测试用量明确标记；真实模型联调单列成本授权。按模型调用而非 UI 重放核对使用量，缓存统计与费用来源明确；不在本任务承诺生产级财务账本。
10. **旧资产按能力评估**：旧进程桥接运行完整 Agent 且随连接关闭终止，仅供 A 原型参考；旧队列是进程内串行化参考，旧计量是 PoC。复用有证据支持的部分，不默认整体继承或全面重写。
11. **实现归属与界面边界**：实现接入放在自有层，复用上游能力而不直接修改其源码。沿用现有界面和事件表达；若确需新增 UI，先经过项目要求的原型确认，本任务不跳过该门禁。
12. **交付范围固定**：不提供工期、固定空闲回收时间或固定并发保证。首阶段只清理明确终止的测试资源；生产容量、身份系统、留存和回收策略留给后续部署规格。

## Testing Decisions

### 测试原则与模块范围

- 只断言外部行为：输入任务、输出事件、工具结果、产物、状态和权限结果。不测试私有函数调用顺序，也不以某个类或队列的存在证明可靠性。
- 主缝隙覆盖会话访问入口、完整 AgentHost、执行适配与产物读取；辅助测试验证 SDK 工具契约。隔离与进程生命周期使用真实执行环境，Mock 只用于确定性模型响应和可控故障分支。
- B/C 使用相同内容但互相独立的样本，覆盖主架构文档 V1–V10。用包含多次工具调用的完整会话验证读取、编辑、命令和产物，不只分别调用四个适配器方法。
- 在接受确认前后、运行期间、终态回传之前分别断开连接，检查是否被拒绝、能否查询原操作或明确返回未知；观察端重连不得再发命令或重复计量。
- 取消、超时、执行环境异常退出和 B 宿主停止分别测试；确认进程状态与文件实际结果，不能仅断言 UI 显示了错误。
- 负向场景覆盖两个独立测试工作区的身份篡改、绝对路径/路径穿越/符号链接，以及获准的网络阻断测试。通过受限场景只证明对应策略，不声明普遍防逃逸。
- 本地回归覆盖既有会话恢复、分支、compaction 和所用扩展；依赖或样本不足时记录阻塞，不将跳过算通过。
- 测试路径使用平台兼容比较与临时目录，禁止硬编码开发者本机路径；不得使用生产凭据、生产数据或未经授权的付费服务。

### 已有测试先例（只读参考）

以下是 Power Web 上游应用测试，不是 SDK 的远程沙箱测试：

- [agent-client.test.mjs](../../lib/agent-client.test.mjs)：区分明确的 prompt 拒绝、普通 HTTP 错误与传输故障；只有显式拒绝确认才是确定的否定结果。
- [agent-event-stream.test.mjs](../../lib/agent-event-stream.test.mjs)：启动较慢时先打开 SSE、订阅与快照顺序、流内启动错误，以及启动期间客户端取消。它不证明远端任务已能脱离连接长期运行。
- [agent-event-wire.test.mjs](../../lib/agent-event-wire.test.mjs)：增量投影、工具标识、快照覆盖的事件过滤及流量随输出近似线性增长。它不提供持久事件日志或副作用幂等保证。

这些测试使用 `node:test`、断言与可控替身，可借鉴其外部契约风格；本任务不修改这些上游文件。新增远程执行和真实隔离验证应放在自有层。本轮没有验证现成容器测试覆盖，不能声称其已存在或已经通过。

### 准入与退出门禁

1. **准入**：列出允许的测试环境、样本、执行入口和跨边界能力；确认没有生产数据与共享凭据。缺少真实执行环境时可以先写契约测试，但必须将对应集成门禁保留为阻塞。
2. **退出**：V1–V10 必做结果及 C 回归具备可复现记录，注明版本、运行环境、通过项和未覆盖项；任何必做项失败或缺失，不得把任务标为完成。
3. **输出**：验证报告区分现有能力、此次新增验证和仍待验证事项；按失败结果修正规格，不把临时绕过当成正式架构。
4. **不得自动晋级**：首阶段通过不等于 A 或团队平台可用；A 的客户端离线连续性及多租户/容量门禁必须在后续任务验证。

## Out of Scope

- 在本任务中实施 A 的生产托管、团队 SSO 上线或开放多人真实数据访问；这些仍是后续团队交付目标，不是被否定的方向。
- 活跃会话自动迁移、透明 A/B 切换、本地与云端自动双向文件同步、自动每任务 worktree 和合并编排。
- 移动端原生 Shell、系统推送、依赖后台常驻的完整本地 Agent；移动端先用 A 是后续建议，不是本任务的新 App 交付。
- K8s 预热池、跨公网多云调度、商业支付结算、生产财务账本，以及未经测量的规模或时限保证。
- 重写已有会话宿主、全量重构旧 Gateway、修改上游源码、改写历史 ADR 或用新项目定位取消开发约束。
- 未经批准使用付费模型/沙箱、发布、推送或执行其他高风险外部操作。
