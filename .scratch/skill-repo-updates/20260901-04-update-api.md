## 要做什么

新建 `app/poweri/api/skills/update/route.ts`（**不动上游 `app/api/skills/update/route.ts`**）。沿用 PowerI 市场路由的 `action` 约定（见 `app/poweri/api/skills/market/route.ts`）：

```
POST /poweri/api/skills/update
  { action: "check", folder? }                      → { updates: [...] }
  { action: "apply", folder }                        → { success, before, after, changedFiles }
  { action: "apply", subscriptionId }                → 源级批量，返回逐项数组
  { action: "apply", folder, mode: "force" }         → 覆盖 conflict
  { action: "apply", folder, mode: "keep" }          → 放弃远程改动：把基线推进到当前本地状态，badge 清空
```

### apply 单条算法（顺序即正确性）

1. `force` 同步该订阅源（绕过 TTL，见 [03](./20260901-03-check-ttl-update-state.md)）
2. 取登记表；`origin: unknown` 或无记录 → **400 拒绝**，绝不覆盖判不出来源的目录
3. `remoteTreeHash()` == 登记 `sourceTreeHash` → `{ success: true, unchanged: true }` 直接返回
4. `localDirHash()` != `baselineLocalHash` 且 `mode !== "force"` → **409** `{ error: "conflict", localHash, baselineHash, remoteHash }`
5. **先算变更清单再动手**：比对旧副本与缓存新版目录 → `changedFiles: [{ path, kind: "added"|"removed"|"modified" }]`。浅克隆没有历史提交，`git log/diff` 不可用，文件级比对是唯一零成本来源（这就是 UI 展开区要显示的东西）
6. 原子替换：`cpSync(cacheSrc, "<folder>.new-<ts>", {recursive:true})` → 若该 skill 原本休眠（读旧 `SKILL.md` 的 `disable-model-invocation`，或登记表 `disabled`）→ 对**新副本**调 `setDisableModelInvocation(newContent, true)` → `rename(folder → folder.old-<ts>)` → `rename(.new → folder)` → `rm(folder.old, {recursive:true})`
7. 任一步失败 → 回滚：把 `.old` 改回原名、删掉 `.new`，返回带原因的 500；登记表**不写**
8. 成功后 `upsertInstall({ sourceTreeHash: 新值, baselineLocalHash: 重算, updatedAt: now })`

### 要点

- 第 6 步的开关回写顺序不能换：先复制再回写，回写放在 rename 之前，保证落到磁盘上的正式目录永远是"完整且带正确开关"的状态
- 临时目录与正式目录同级（同一个 `~/.pi/agent/skills/`），否则跨分区 rename 退化成拷贝、失去原子性
- 批量更新串行执行（不用 `Promise.all`）：单条失败不影响其余，逐条回报，日志可读
- 请求校验与错误响应形状照抄同层路由 `app/poweri/api/skills/toggle/route.ts` 的现有做法（它是 PowerI 持有，已定下风格），不自创一套
